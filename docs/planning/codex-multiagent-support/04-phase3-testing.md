## 3.4 — Unit-тесты: инсталлятор (Go table-driven, по прецеденту `install_e2e_test.sh`, но для Go-логики merge)

По находке критика фазы 2 (`bin/install_e2e_test.sh`/`install_test.sh`/`mock_server.py` — существующий харнесс, но bash-уровня для shell-инсталлятора; для Go-уровня merge-логики нужны отдельные Go-тесты в tmpdir):
- Merge в пустой/несуществующий `hooks.json` — создание с нуля.
- Merge в существующий hooks.json с чужими (не owner-marked) записями — чужие не тронуты.
- Повторный `codex-install` (идемпотентность) — owner-marked записи заменены на канонические (ревизия 2.3/2.4: canonical-reset, не "не трогать руками правленное").

- `codex-uninstall`: owner-marked записи убраны, чужие остались, backup удалён ТОЛЬКО после успешной верификации (ревизия 2.7) — тест, что backup СОХРАНЯЕТСЯ при смоделированном сбое верификации.
- TOML-путь (2.5 ревизия): текстовая вставка `notify=[...]` перед первым `[table]`-заголовком (не в конец файла) — тест на конфиг с секциями И без секций; тест, что комментарии/форматирование остального файла не изменились (byte-diff вне нашего добавленного блока).
- Legacy-uninstall: `notify`-запись убрана из config.toml хирургически, остальное содержимое byte-identical.

## 3.5 — Live/manual e2e тест-план (обязателен перед релизом, не автоматизируется полностью)

Реальный Codex CLI, реальная установка через `codex-install`:
1. Свежая установка на систему без `~/.claude/` вообще (чистый Codex-only юзер) — подтвердить `MkdirAll`-цепочку работает на каждом уровне (lock-файл, config.json, hooks.json).
2. `/hooks` trust flow — подтвердить реальные шаги, обновить текст 2.6, если разошёлся с реальностью.
3. Триггер `Stop` на реальной Codex-сессии — уведомление приходит, звук играет, click-to-focus поднимает правильное окно/pane.
4. Триггер `PermissionRequest` (реальный tool-call, требующий approval) — уведомление приходит с корректным `tool_name`; отдельно — подтвердить/опровергнуть research-item 3.1 п.6 (bypassPermissions/dontAsk и правда не фаерят событие).
5. Continuation-цикл (Codex несколько раз продолжает после Stop) — подтвердить `stop_hook_active`-подавление не даёт дублей, но и не глотает легитимные отдельные Stop.
6. Повторная установка (идемпотентность) на уже настроенной системе — hooks.json не растёт, записи заменяются, не дублируются.
7. Установка на систему БЕЗ поддержки hooks.json (если удастся найти/собрать старый Codex, иначе — форсировать legacy-путь флагом для теста) — legacy notify работает, PermissionRequest корректно НЕ приходит с явным предупреждением при установке (2.6 legacy-ветка).
8. `codex-uninstall` — hooks.json/config.toml возвращаются к состоянию без наших записей, чужие записи (если тестово добавить сторонний хук) не пострадали.
9. Гонка "install во время запущенного Codex" (намеренно, для проверки content-hash guard) — подтвердить видимый retry, не тихий hang, не порча файла.
10. Windows-специфично: символических путей нет — подтвердить `.exe`-путь в hooks.json работает через реальный `/hooks` trust (это первый раз, когда non-symlink стабильный путь проверяется вживую).

### 3.1 — 5 из 7 research-items ЗАКРЫТЫ реальным веб-ресёрчем (p3-critic-research, с источниками)

**Метод (а) сработал для 5 пунктов, не был чисто теоретическим** — критик реально сходил в веб и codex-rs-производные источники и закрыл:

Источники: learn.chatgpt.com/docs/hooks (официальная дока), pkg.go.dev/github.com/ajbeck/scut/hooks/codex (независимый Go-декодер, совпадающие struct-теги).
- **П.2 (session_id формат) — ЗАКРЫТО, ОБРАТНО моей гипотезе**: **hex-UUID (UUIDv7)**, НЕ ULID. Реальные примеры (`019b4087-c66f-7f93-8e19-f26a7b79cd90`). **Важно**: FNV-фолбэк в 1.7 Фазы 1 НЕ становится обязательным — остаётся защитным. - **П.3 (stop_hook_active семантика) — ЗАКРЫТО, план был прав**: true = "следующая попытка после заблокированного стопа / предотвращение continuation-цикла", идентично Claude Code.

- **П.7 (легаси notify payload) — ЗАКРЫТО с точными полями**: kebab-case, ARGV (не stdin): `type=agent-turn-complete, thread-id, turn-id, cwd, client(опционально), input-messages, last-assistant-message`.

**Не закрыто — честно, не от нехватки времени**:

### 3.4 — тестовая архитектура сделана implementable (p3-critic-installer-tests, с кодом)

**Content-hash guard тест НЕДЕТЕРМИНИРУЕМ без явного production test-seam** — план должен МАНДАТИТЬ инъектируемый hook в merge-функции, срабатывающий строго между hash и rename (не горутина+`time.Sleep`, будет флейковым):
```go
type hookMerger struct { afterHash func() } // nil в проде; тест пишет файл здесь
func TestMergeHooks_ConcurrentWriteAbortsAndRetries(t *testing.T) {
    // afterHash пишет "внешнего писателя" один раз → assert retry сработал ≥2 раз,
    // финальный результат содержит И наши записи, И конкурентную правку (не затёрта)
}
```
Модель угрозы уточнена: гонка — с ВНЕШНИМ не-локирующим процессом (сам Codex/юзерский редактор), не со вторым нашим инстансом (тот сериализован flock'ом).

**Windows rename-retry — разделить на два теста, не один**: (a) детерминированный, кросс-платформенный LOGIC-тест с инъектируемой `renameFn`, фейлящей N раз по КОНКРЕТНОМУ errno-предикату (`ERROR_SHARING_VIOLATION`/`ERROR_ACCESS_DENIED`, matched через `*os.LinkError`→`syscall.Errno`, не строкой) — таблица `{failN, maxN, wantCalls, wantErr}`; (b) реальный OS-level тест, `//go:build windows`, best-effort, **`t.Skip()`, не `t.Fail()`**, если сценарий не воспроизвёлся детерминированно (антивирус/индексатор — не мы). (b) переносится в 3.5/3.6 (не 3.4 — недетерминирован по своей природе).

**"byte-diff вне блока" — верно ТОЛЬКО для TOML, НЕ для hooks.json**: TOML (текстовая вставка) → byte-golden fixture в `testdata/` реализуем и правилен. hooks.json (parse→merge→marshal) → re-marshal нормализует порядок ключей/отступы — byte-diff даст ложные падения; нужна **структурная** проверка (unmarshal оба, deep-equal чужого поддерева + каноничность наших записей).

**Underspecified, требует пиннинга до написания тестов**: owner-marking механизм (уже уточнён в ревизии Фазы 2 — токен-подстрока `--owner=`, не exact-match — тестируемо); "malformed hooks.json" — два отдельных теста (невалидный JSON vs валидный-но-неожиданной-формы); TOML-без-секций — вставка в конец файла, если заголовков `[table]` нет вообще (уточнено в ревизии Фазы 2); hermeticity — installer-тесты через `HOME`-override ИЛИ path-injection DI (НЕ реальный `~/.codex`, в отличие от teamstate-тестов, которые пишут в реальный `statePath()` с `defer os.Remove` — так для инсталлятора нельзя); `HOME`-override процессо-глобален → content-hash тест НЕ должен быть `t.Parallel()`.

### 3.6 — CI-гейтинг переписан под реальность (Codex e2e физически не может быть обычной CI-джобой)

- `notifier-signing-smoke.yml` — `workflow_dispatch` (ручной триггер) — для дорогого/секрет-зависимого прогона.

**Новая стратегия**: класс B (№7, легаси) — env-var-gated ЛОКАЛЬНЫЙ opt-in (имя переменной зафиксировать, ПЛЮС SKIP-побратим `..._SKIP_CODEX_CLI=1`, как в прецеденте — принудительно выключать, если codex случайно оказался в PATH раннера), модель через `-codex-model` флаг (не хардкод, ротация моделей), `--ephemeral` обязателен. **Обязательный трёхслойный skip** (не fail) по прецеденту `codexBinaryOrSkip`: env-флаг → бинарь в PATH → `codex login status` ок → иначе `t.Skip()`; плюс skip на нездоровый рантайм.
