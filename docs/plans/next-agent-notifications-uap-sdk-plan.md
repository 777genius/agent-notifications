# Следующий агент: Gemini CLI через Universal Agent Plugins

Статус: исправлен после трёх последовательных независимых reviews R1/R2/R3; финальный R3 `an-next-review-r3`, 1 октября 2026. Plan findings закрыты, дальнейшая обратимая реализация/TEST выполняется автономно. Выбор — **Gemini CLI 0.62.0**, два автоматических сигнала: нативный `AfterAgent` и `Notification: ToolPermission`. Реализация находится в отдельных UAP PR #364/#365 и Agent Notifications PR #281–#286. Нативные G0/G5 прошли на macOS arm64 и Linux amd64/arm64; оба macOS-баннера владелец визуально подтвердил. Windows amd64 и macOS Intel пока не прошли финальный native gate. Выпуска Gemini ещё нет. Первый результат — тонкий работающий маршрут для одного агента, с reusable SDK и нативными mechanics в UAP с первого production commit; политика уведомлений и доставка — в AN.

## 3. Нативная проверка G0 и автономное выполнение

После R3 выполнять обратимую реализацию и TEST-проверки самостоятельно. G0 уточняет wire contract и native installation до фиксации публичного API; экспериментальный SDK handler/fixture и reviewable candidate можно готовить до завершения G0. Не требовать отдельного owner confirmation для веток, локальных артефактов, TEST-профиля, реализации или исправления тестов. Публикация остаётся отдельным checkpoint (§8). Здесь нет отдельного проекта whole-agent trust management: owned hook contract, effective-policy ограничения и проверенный TEST startup достаточны.

1. Зафиксировать package identity **Gemini CLI 0.62.0** и сопоставить нужные call sites с официальным v0.62.0 commit. Не запускать настоящий профиль ради discovery. Проверить GATEWAY startup, hook input/output, Notification matcher, timeout в ms, вызовы `AfterAgent`, отмену/continuation и фактический native shell. Source types уже подтверждают session/timestamp, notification_type/message/details и stop flag; native turn/request/parent ID нет. Source API: [contentGenerator.ts](https://github.com/google-gemini/gemini-cli/blob/v0.62.0/packages/core/src/core/contentGenerator.ts). Достаточны конкретные call sites/официальный контракт и соответствующие наблюдения; универсальный trace proof для всех режимов не требуется.
2. Создать приватный disposable lab `TEST` с отдельными profile, AN control/runtime/config и evidence. Только синтетическое содержимое; настоящий repository не использовать как задание/cwd/target. Запускать child с новой минимальной allowlisted env, без наследования owner env/auth/proxy/custom headers. HOME/USERPROFILE/XDG/temp — lab; точный `utils/paths.ts` 0.62.0 должен подтвердить effective `homedir()`/HOME/GEMINI_CLI_HOME и settings root, одного UAP detector недостаточно. Установить `GEMINI_CLI_SYSTEM_SETTINGS_PATH`, `GEMINI_CLI_SYSTEM_DEFAULTS_PATH`, `GEMINI_CLI_TRUSTED_FOLDERS_PATH` на собственные TEST files. **`--ignore-env`/`advanced.ignoreLocalEnv` не отключает discovery:** settings source продолжает искать trusted `.gemini/.env`, HOME `.env` и родителей. Простой TEST layout: `cwd == verified homedir() == <TEST>/profile`, user settings — `<TEST>/profile/.gemini/settings.json`; создать собственные пустые `<TEST>/profile/.gemini/.env` и `<TEST>/profile/.env`. По exact `findEnvFile` trusted/untrusted ветка должна выбрать свой sentinel сразу, до ancestor traversal; ignore-env включён дополнительно. Это разрешённые синтетические TEST файлы, не owner dotenv. Проверить остальные startup reads и system-policy paths до native запуска; trusted execution scope сам по себе не доказывает isolation. Если конкретный read не изолирован, исправлять TEST layout/поддержанные настройки и не запускать этот сценарий до закрытия именно этого риска; security guard не менять.

Основной воспроизводимый путь — **реальный неизменённый CLI + deterministic local HTTP provider fixture**. `GOOGLE_GEMINI_BASE_URL` выбирает `AuthType.GATEWAY`, поддерживает local URL и пустой API key без OAuth. ## 4. Runtime: native facts в UAP, уведомления в AN

| Native event | SDK / политика AN | Фиксированный пользовательский текст |
|---|---|---|
| `AfterAgent` | Existing typed SDK event; означает наблюдение documented AfterAgent в проверенном CLI flow. AN status `task_complete` используется для настройки канала, не как доказательство успеха задачи. | «Gemini CLI завершил ход» |
| `Notification`, subtype `ToolPermission` | Новый typed advisory SDK event; другие subtypes молчат. AN status `permission_request`. | «Gemini CLI запросил разрешение на инструмент» |
| `SessionStart`, `SessionEnd`, `BeforeAgent`, model/tool hooks, неизвестные events | Existing SDK contracts сохраняются; первый product consumer не устанавливает эти observers и не ведёт turn lifecycle. BeforeModel — только дополнительный TEST text case. | Ничего |

`AfterAgent` не доказывает успешное выполнение задачи, отсутствие error/cancel или окончательное исчерпание всех чужих hooks. `stop_hook_active` — native признак hook continuation/recursion, **не event ID и не общая метка transport retry**. Начальная AN policy подавляет completion при `true`, чтобы не дублировать продолжение, инициированное блокирующим hook; первый `false` может предшествовать такому продолжению. Не обещать final-only completion в присутствии blocking AfterAgent hooks. G0 проверяет это поведение, а не ищет обязательный последующий «terminal false». Если cancel порождает неотличимый AfterAgent, generic текст описывает факт завершения хода без утверждения успеха; это ограничение документируется. Если AfterAgent при cancel отсутствует, completion не синтезируется из SessionEnd/transcript.

Root/main scope устанавливать узко по call sites/официальному контракту проверенной версии и обычному CLI сценарию. Native DTO не содержит parent/root flag: не делать `RootSession=true` по умолчанию, не объявлять фильтрацию всех вложенных sessions или parity экспериментальных subagents. Если конкретный nested режим использует тот же hook без discriminator, явно исключить этот режим из обещания main-only поддержки. Не запрещать обычный CLI маршрут из-за отсутствия универсального доказательства. Question/elicitation, plan/review, terminal error classification, subagent completion, IDE/cloud, focus и sound в первый scope не входят; не выводить их из текста/tool arguments.

**UAP SDK:** добавить `OnNotification`, typed event/subtype и пустой advisory response через существующие `sdk/gemini`, `sdk/internal/platforms/gemini`, descriptor defs и штатную генерацию registrar/resolver/support entries. Добавить alias в ручной `sdk/internal/runtime/names.go`, согласовать beta capability/support metadata; не превращать прежний stable nine-hook extension renderer в ten-hook generator. Invocation **`GeminiNotification`**; bare `Notification` остаётся Claude. SDK сообщает настоящие `session_id`, `timestamp`, `notification_type`, `message`, `details` из exact native types; AN source отбрасывает message/details и остальные sensitive fields. Никаких fabricated turn/request/parent ID или normalized cross-agent event bus. Публичный observer response не предлагает allow/deny/context; результат `{}`. Это документированный observer subset Notification API, не обещание реализации всех native output options. Новый contract — public-beta до соответствующей qualification, существующие 9 handlers не менять. Neutral mechanics доступны любому SDK consumer с первой реализации, не извлекаются позже из AN. Небольшой independent process consumer импортирует только public SDK и регистрирует оба handlers без AN/config/webhook imports; он доказывает reusable seam, без нового example framework. Existing SDK mismatch warning/argv policy других hooks не ужесточается этой задачей.

**AN:** `internal/geminisource` по образцу buffered Codex adapter **до отбрасывания decoded event проверяет** native `hook_event_name` против trusted command selector; SDK dispatch по argv не считается такой проверкой. Возвращает узкий DTO: native session/timestamp, validated kind/subtype, stop flag. Raw SDK event, prompt/response, cwd/transcript/tool/message/title не выходят из source. `internal/geminievent`, `cmd/claude-notifications/gemini_event*.go` и явный command route вызывают существующий `DeliveryPort`/webhook pipeline. Schema v2/merge остаются существующими; новая schema не нужна. Webhook получает явный `agent_source=gemini`, а `agentDisplayName` в `internal/webhook/formatters.go` — friendly имя Gemini CLI. Existing normalizer уже сохраняет непустой source; только пустой source defaults to Claude, его не менять. Native decoding/command rendering/owned hook parsing остаются в UAP; business copy, channel choice, consent и admission — AN.

**Корреляция и минимальная защита от повторов.** Не строить durable delivery journal, session epochs, monotonic turn counter, request-resolution graph или resume tombstones для двух observers. Уже имеющийся `internal/agentnotify/journal` рассчитан на иной RPC/idempotency contract с retention минимум 7 дней; его перенос сюда без native key не добавит гарантий. Старый `internal/dedup` вставляет raw session ID в filename и также не подходит напрямую.

В AN достаточно одного приватного bounded recent-observation cache: ключ — length-prefixed hash `(installation ID/generation, gemini, native session, native event, subtype/stop flag, native timestamp)`, плюс channel bits. Timestamp — часть marker наблюдения, **не уникальный turn/request ID**. До выбранного эффекта атомарно отмечать попытку данного channel под существующим lock, хранить только hashes/bits/локальное время истечения. Начальный бюджет — 60 s, максимум 256 markers, clock/atomic file primitives существующего AN; cache не является очередью и не replay-ится. Нет native timestamp — разрешена одна попытка на данный hook invocation, без обещания защиты между процессами. Нет обязательного session/kind либо cache/lock недоступен — neutral suppression с фиксированной classification. Обычный native flow не должен зависеть от BeforeAgent/state восстановления.

Гарантия ограничена: повтор того же marker в cache window не даёт второй попытки данного channel; crash после отметки может потерять уведомление. Retry с новым timestamp, collision timestamp, eviction, потеря cache или новый boot не дают exactly-once гарантии. Resume не переигрывает product events; новые CLI-emitted observations обрабатываются обычно. Два одинаковых по тексту хода не объединяются по тексту; prompt hash вообще не вычисляется. Permission signal не имеет придуманного request ID; нет обещания одного alert на tool request/logical turn, текущего pending состояния или отзыва уже показанного баннера. Корреляция означает installed binding + native session + конкретное наблюдение; внутренний случайный `CorrelationID` доставки не выдавать за native ID.

**I/O и deadlines:** один bounded JSON object, SDK `MaxPayloadBytes` (1 MiB), typed SDK decode и existing unknown-field behavior. Не добавлять bespoke case-fold/duplicate-key parser и не ужесточать payloads других агентов: `runtime.DecodeJSONPayload` уже использует `json.Unmarshal`, rejects syntax/trailing/type errors. Проверять нужные scalar fields и event/subtype; unknown extras не расширяют capability. При необходимости ограничить сложность existing validator — обосновать конкретный риск, не вводить новый protocol gate.

Buffered source захватывает SDK stdout/stderr; product entrypoint отвечает только `{}` + exit 0 при decode/panic/cache/delivery failure, без raw errors. Existing `process.ReadStdin` не прерывает blocked pipe; закрытие собственного stdin при deadline — маленькое entrypoint seam и отдельный process test, без нового middleware framework. Начальные budgets: native timeout 5 000 ms (сверить installed contract), stdin 1 s, lock до 250 ms, total 4 s. Backend получает remaining budget и существующий boot-continuous `Deadline`, без обновления после suspend. Внешний kill не обещает exit 0.

Webhook `SendWithContext` сейчас принимает business DTO, а `New` создаёт background context и HTTP timeout 10 s: это **не** выполнение бюджета hook. Добавить обратно совместимый AN sender seam с parent `context.Context`/deadline и переиспользовать payload/transport; прежние callers сохраняют default. Здесь retry выключен, максимум одна попытка каждого согласованного channel, без replay после unknown/cancel. Desktop и webhook независимы: оба заранее выбранных channel могут получить по одной попытке; ошибка одного не включает другой как fallback и не разрешает повтор.

**Privacy/consent:** title/body только фиксированные строки. Config для webhook санитизировать по существующему `privateWebhookConfig`: убрать headers/payloadFields/enrichment, отключить retry, заменить status title; передавать только status/body/`agent_source=gemini`, без native IDs/paths/agent text. Existing transport destination/auth не копировать в receipt/evidence. Пустые session/project fields готового formatter не означают утечку native data. Debug/receipt/cache не содержат Raw/error cause. Desktop и webhook выбираются отдельно для Gemini, revalidate consent/registration непосредственно перед handoff; Claude/OpenCode webhook choice не разрешает Gemini. Не читать transcript ради enrichment, event classification или correlation.

## 5. Тонкая установка и существующая доставка

Первый маршрут — **два named command hooks в user `<effective-config-root>/settings.json`**. Это штатная native форма, не Gemini MCP/skill и не вызов YAML authoring engine. Hook-only extension, portable `plugin.json` projector, `PlanQualifier`/`TargetLayout`, extension metadata, enablement-file codec и link/update engine **не нужны для этой vertical slice**. Их existing implementation сохраняется; расширять `agentplugins` skills/MCP adapter только ради уведомлений не следует. Не добавлять daemon/универсальный installer/новый install ledger.

Reusable нейтральный UAP seam, рабочее имя `install/integrationctl/agentplugins/geminihooks`: pure `Plan`/`VerifyOwned`, explicit config root/target OS, operation **install/update/remove**, existing settings bytes и previous own receipt; каждый `HookSpec` содержит native event, unique name, fixed argv, matcher и timeout ms. Выход — desired bytes, два owned-group digests и no-op/conflict classification. Никаких FS writes, discovery/auth reads, AN consent или произвольного executable script callback. Пакет находится в уже существующем nested agentplugins module, не создаёт новый Go module и не импортирует CLI/YAML engine; portable installer.Engine/projector не prerequisite. Имена hooks/command/target задаёт consumer; текста Agent Notifications в UAP нет. Public API допускает независимый consumer с другим binary/name; его contract fixture не импортирует AN.

Legacy `helpers_hooks_gemini` — extension codec, **не готовый user-settings codec**: `map[string][]group` ломается на native `hooks.enabled`, `hooks.disabled`, `hooks.notifications`; DTO теряет name/timeout/env. Новый narrow hooks planner сохраняет top-level/foreign hooks и reserved fields как AST/raw values, меняет только два собственных singleton groups в `AfterAgent` и `Notification`. Reuse/adapt document/canonical-entry primitives existing `nativeconfig/document.go`/hujson; MCP `Codec`/receipt не переименовывать в hooks. Gemini settings принимает comments: сохранять корректную comment-bearing конфигурацию; подтвердить grammar parity с native comment stripping, не молча чинить malformed input или расширять native syntax. Duplicate ambiguity в изменяемом месте даёт conflict existing document policy, без нового strict wire parser для hook input.

Собственный digest связывает event и **весь влияющий на исполнение own group**: matcher/sequential, name/type/command/timeout/env и unknown members. Receipt с native selectors/digests/config path — один маленький registered host artifact под существующим AN ledger, не новый install ledger и не копия settings. Foreign name collision, duplicate own names или edit own group → conflict; identical command без receipt не усыновляется. Не менять global enabled/disabled/trust и не сохранять в receipt чужие bytes. Pure VerifyOwned проверяет только own groups; effective activation дополнительно доказывает actual CLI G0. Legacy nine-hook authoring semantics/services/tests сохраняются: выделить только реально общий neutral helper, иначе selective adaptation в новом пакете без wholesale перемещения старого caller. Сохранение source не требует поддерживать второй YAML продукт.

AN `internal/geminiinstall` повторяет существующий OpenCode host composition: `installruntime.Request` с fingerprinted binary/own receipt, `ConfigPaths` для native settings, `Prepare` вызывает pure UAP planner **под existing component/config locks**, далее existing CAS/journal/recovery. Весь `settings.json` не становится managed file: `transaction.go` специально исключает `ConfigPaths` из `Ledger.Files`; foreign JSON edits должны оставаться возможными. Ownership двух entries хранится в собственном receipt, registered consumer проверяет receipt/runtime и UAP `VerifyOwned`, а не digest всего native config. AN не содержит второй native parser/quoting implementation. `nativeconfig.BeginExactFile` остаётся reusable UAP writer для иных hosts; не вкладывать его второй lock/transaction внутрь этого AN commit.

Узкие обязательные host adaptations: `route.geminiNotifications` для двух channel consents; damaged-asset revoke по образцу **строго OpenCode-specific** `RevokeOpenCode`/`openCodeRevokeOnly` — добавить ограниченный Gemini вариант, не присваивать чужое поле и не разрешать произвольный bypass проверок. Revoke доступен даже при повреждённом runtime/receipt. Не переносить `OnCommittedBinding`/portable Engine handoff без реального потребителя.

**Paths/commands:** existing `geminiHookCommandCandidates` лишь соединяет строки и extension placeholders. В U2 нужен маленький public argv renderer для **проверенного target shell**; каждый token quoted, absolute trusted binary и owned roots/flags, никакой `${extensionPath}` или stdin interpolation в user hooks. Gemini сначала вызывает `resolveEnvVarsInObject`, поэтому **shell quoting не доказывает сохранение literal token**: exact resolver проверяется в G0, затем путь settings expansion → effective command → native shell → actual argv. Variable-like token, который невозможно сохранить штатной формой, даёт явный unsupported-path conflict; не создавать общий interpolation engine. Установить ровно два commands с trusted event selectors; AN source сверяет selector и native hook_event_name до business dispatch. G0 проверяет фактические argv/.exe/spaces/non-ASCII и native shell; contract cases — drive/case aliases, `$`/`${...}`/backticks, quotes, Windows `%`/`&`/`!`. Unsafe/unsupported shell/path form → explicit conflict без fallback, не универсальная shell abstraction. JSON escaping не shell escaping. Следовать existing canonical/no-follow/reparse/path restrictions; не строить новый filesystem framework. Native settings неизвестные поля сохраняются семантически; formatting/comments могут измениться, гарантию byte preservation не давать. Остаточная внешняя writer race и ACL/xattrs ограничения existing writer документируются. Mode/private ownership проверить существующими primitives.

**Delivery:** existing `DeliveryPort`, `NewStructuredDelivery`, `NewFreedesktopDelivery`, `WindowsToastDelivery`. Mac `opencodeinstall.NativeInstallation.Acquire` уже revalidates policy и держит lease; адаптировать consumer-specific registration в небольшой Gemini wrapper. Shared AN helper identity/manifest/OS consent сохраняются. Private spool preparation переиспользует existing no-follow primitives с собственным фиксированным Gemini namespace; не копировать весь OpenCode spool service и не добавлять callback lifecycle для Navigation=None. Windows identity hardcoded в factory **и COM .lnk staging/readiness**: один compile-time trusted Gemini spec (consumer/AUMID/shortcut name) параметризует нужные existing helpers, прежние OpenCode functions остаются wrappers с теми же constants/ownership semantics. Gemini setup stage и toast readiness используют один spec; shortcut только desktop, owned removal только Gemini. Не копировать COM/PowerShell/XML/backend implementation, не использовать OpenCode identity и не строить generic OS/plugin factory registry. Выделение малого identity helper допускается лишь для устранения фактического import cycle.

Recent-cache lock освобождается до effect lease. Один владелец lease на channel: Mac NativeInstallation adapter; Linux/Windows/webhook host wrapper через `AcquirePolicyLease`. Нельзя outer lease + повторный backend Acquire того же component lock. Внутри handoff проверить соответствующий channel и поколение; bounded effect завершает lease, затем revoke может завершиться. Windows native remove busy exe — existing temporary verified copy. `Navigation=None`, `SoundEnabled=false`, `Silent=true`. Unavailable desktop/session → fixed classification, без shell fallback/повтора после возможного эффекта. OS permission setup вызывается явно из setup TEST flow, не из каждого event.

**Setup:** no-args `bin/setup.sh` сейчас ведёт в single-choice bootstrap, поэтому four-product multiselect нужно реально подключить. Маленький AN entrypoint, рабочее имя **`setup-products select`**, использует существующий public UAP `installerui.SelectMany` и возвращает только validated product IDs/channel choices. Loader получает проверенный helper того же candidate/release, открывает controlling TTY (stdin curl pipe не является UI), вызывает selector **до install mutations**, затем исполняет существующие product routes для любого непустого subset `claude,codex,opencode,gemini`. Cancel/empty selection → zero mutation. Не менять `portablesetup.NewRegistry` или Claude/Codex unit/MCP wizard ради этой UI; Gemini/OpenCode идут в свои hook/delivery hosts. Сохранить `--product`/`--products`, partial-success и прежние scopes. Реализованный singleton/mixed selector использует общие `--desktop`/`--webhook` для каждого выбранного observer (Gemini/OpenCode), с раздельной записью согласия по агентам; `--skip-agent-notify` относится к Claude/Codex. Специальные `--gemini-desktop`/`--gemini-webhook` не введены: это уточнение реализации для единой команды установки. Все выбранные products/channel choices/capability preflight завершаются до первой mutation; noninteractive без Gemini channel choice отказывает сразу. Это согласие пользователя продукта на delivery, не owner approval реализации. Gemini lifecycle — явный **`setup-gemini install/update/remove/inspect/recover`** поверх existing transaction; CLI flags/help окончательно сверяются с actual parser в G4.
